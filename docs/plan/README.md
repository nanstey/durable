# Durable, proactive agents as the base of the portable harness

> **Plan location:** this plan lives in the public repo [`nanstey/durable`](https://github.com/nanstey/durable) at `docs/plan/` (it was drafted under the skills repo's `.plans/` and moved). Paths in the documents are repo-root paths of the **durable repo** unless marked "skills repo". Public-repo rules apply to every file here: no secrets, machine-local state, absolute or personal paths, real host or tailnet names, emails or private repo names.

- Status: planning (revisions 1-6 applied; awaiting user re-review)
- Summary: Rebuild the harness around Pi Durable: one durable steward process per project scope per machine, one **profile** per agent (credentials stay in machine-local profiles), workers dispatched through a `WorkerDispatcher` adapter (Orca primary), a code-owned review/merge gate that works under the operator's shared GitHub identity, per-repo opt-in auto-merge behind a pluggable `RepoPolicySource` seam (mechanism undecided; auto-merge off by default via the `none` source) proven by shadow mode, a layered control plane (CLI/TUI, local notifications, and a multi-machine web console served from one chosen machine over Tailscale, interactive from any browser, a phone included, with identical capabilities), an additional Android/Termux daemon target behind platform capability flags, and retirement of interactive subagents. Our API, client, TUI and console are written from scratch (the dpi-* projects were inspiration only). The engine lives in the public `nanstey/durable` repo; the skills repo keeps only a thin integration (pinned clone, CLI on PATH, thin skill).
- Tier: large (see Decision log for evidence)

- 2026-10-23 (rev 3, Q9) — **(Superseded by rev 5 Q18: the `.github/durable-policy.yml` file and trust-pin design are withdrawn; only the mechanism-independent invariants survive.)** **Per-repo auto-merge policy lives in the target repo.** Read of "repo rules": GitHub's own rules (branch protection/rulesets, required checks/reviews, merge methods; read via API and computed PR state) **plus** a committed policy file `.github/durable-policy.yml` for the durable-specific parts.
