# Spec 06 — WorkerDispatcher adapters, claims and worker dispatch -> draft PR

Objective: an eligible item is claimed on GitHub, a Pi-session worker implements it in a workspace created through a `WorkerDispatcher` adapter (Orca primary, git-process second) under the profile's identity, and a draft PR appears. Caps, kill switch and crash recovery are enforced.
Design refs: architecture D3, D4, D5, D6, D7, D9, §4 steps 3-4, §5; program design §2 (W1-W3, S1, S2, S4), §3.3-3.4.
Revision 1: adds the adapter layer and contract suite (C7); Orca is assumed present on every machine; PR attribution follows the operator-identity design (C2).
Revision 2: renumbered (was 05). Escalation and budget events now use the notifier from spec 04 (no push services); adds `GET /v1/workers` and `workers` SSE frames for the CLI and console.
Revision 3: dispatcher **capabilities** (`attach`, `steer`, `transcript`) and a live worker transcript tail so the console/CLI can view any worker and steer where the adapter allows (architecture D4, D16); worker routes `POST /v1/workers/<id>/steer` (scope `chat`, `501 not_supported` unless `steer: true`) and `/interrupt` (scope `pause`). Orca terminal-input support is checked against the installed CLI (spike result).
Revision 4: `git-process` must work with no Orca installed and is the default dispatcher wherever Orca is not detected (the Android path, spec 14); dispatcher selection consults platform capabilities; `doctor` skips Orca checks when `dispatchers` excludes `orca`.
Depends on: spec 05 (and spec 04 for notifications).
Size: large. Allowed split at the checkpoint: **6a** items 1-4 (dispatcher + contract suite, observable by launching a trivial job in Orca and in git-process mode), **6b** items 5-13.

## Checklist
1. **Dispatcher interface** `dispatch/types.ts` per program design §2 (`createWorkspace`, `launch`, `status`, `result`, `list`, `interrupt`, `attachInfo`, `removeWorkspace`, `capabilities`; `WorkspaceSpec`, `JobSpec` with `briefText` by value and an allowlist-built `env`). Acceptance: type tests; documented invariants W1-W3 in the file header.
2. **`orca` adapter** `dispatch/orca.ts`: CLI resolution order (`ORCA_CLI_COMMAND` > `orca-dev` > `orca-ide` on Linux outside Orca > `orca`; `machine.yaml` `orca.command` override); `worktree create --name <id> --no-parent --json`; `terminal create --worktree path:<p> --title --command <launcher> --json`; `terminal list --worktree ... --json` before create; `interrupt` and `status` via Orca terminal state; `attachInfo` returns the terminal handle. Check every flag against the installed Orca (`--help`) and record the version in the adapter header (flag-drift risk). Acceptance: recording stub CLI tests (arguments, order, list-before-create, duplicate launch refused).
3. **`git-process` adapter** `dispatch/gitProcess.ts`: `git worktree add` + detached launcher + log file + pid file; `attachInfo` = `tail -f <log>`; dirty-refusing `removeWorkspace`. Also the **test double** for CI. **`fake` adapter** `dispatch/fake.ts` (in memory). Selection `dispatch/select.ts` from `workers.dispatcher` (definition) or `machine.yaml` override; optional `workers.fallback` (off by default; no silent switch). Acceptance: selection tests.
3b. **Capabilities, transcript and steer** `dispatch/types.ts`, adapters: `capabilities()` returns `{visible, resumable, headless, attach: none|read|interactive, steer, transcript}`; `transcript(h)` tails the worker's Pi session JSONL under the per-agent `PI_CODING_AGENT_DIR` (works for every adapter that exposes that directory) and yields text frames; `steer(h, text)` exists only when `steer: true` (`orca` if the CLI has terminal input; `fake` always; `git-process` false); `interrupt` works for all. API: `GET /v1/workers/<id>/transcript` + SSE `workers` frames, `POST /v1/workers/<id>/steer` (scope `chat`, subject to the spec 03 guardrails and rate limits), `POST /v1/workers/<id>/interrupt` (scope `pause`). Reviewer sessions: view only. Acceptance: contract tests for each capability combination; 501 test; transcript tail test with a fake session file; steer text screening reuses the chat guardrails.
4. **Contract suite** `tests/contract/dispatcher.contract.ts` run against `orca` (stub CLI), `git-process` (fake `pi` binary) and `fake`: idempotent createWorkspace/launch, no ambient env forwarded (W1: set hostile env in the parent, assert absent in the launched process), brief passed by value, interrupt soft/hard, `status` transitions, dirty-workspace removal refused, `attachInfo` non-empty. Acceptance: suite green for all three.
5. **Claims** `steward/claims.ts`: label `durable/claimed` + marker comment with agent id and lease; read-after-write; lowest comment id wins; release on loss. Local-file items: local state unless the repo is the agent's. Acceptance: fake-GitHub tests incl. race (two claimants).
6. **WorkItemTask** phases `claim`, `brief`, `dispatch`, `await-pr`, `finish` with intent-first commits and deterministic names (`durable/<agent>/<item>`). Acceptance: replay test: kill between intent and effect, restart, assert no duplicate claim/workspace/job.
7. **Scout brief** `scout/brief.ts`: read-only child conversation (trusted-author items only) writes a brief; `templates/worker-brief.md` (load `idea-to-pr` autopilot; "this workspace is isolated"; forbids merge/force-push/default-branch push; PR must be a draft with the label and marker; no secrets). Acceptance: snapshot of the assembled brief.
8. **Launcher + derived Pi dir** `dispatch/launcher.ts`: `identity/pidir.build`, launcher script 0700 `env -i <job.env> exec pi --model ... --thinking ... "$(cat brief)"`, `DURABLE_WORKER=1`, `DURABLE_AGENT`, `DURABLE_ITEM`; doctor-lite before launch. Acceptance: launcher snapshot; stub `pi`; no ambient env.
9. **Worker guard** `pi-extension/durable-worker-guard.ts` (active only when `DURABLE_WORKER=1`): blocks `gh pr merge`, `git push` to default/protected branches and `--force`, `gh api ... merge`, `--admin`; shares a table with `guard/commands.ts` via a drift test; document it in `docs/workers.md`. It lives in the **durable repo** and is loaded through the generated per-agent Pi settings (a local package path), so no skills-repo install step or Pi-README row is needed; assumption verified here: Pi accepts a local package path in `settings.json`, else the derived pidir makes `extensions/` a real directory of symlinks plus the guard. Acceptance: table tests; sandboxed Pi load test mirroring `harness/pi/tests/package-extensions.test.mjs` if feasible offline.
10. **Monitor** `dispatch/monitor.ts`: find the draft PR by branch/marker/label (GitHub); `dispatcher.status` for liveness. Exited without PR -> re-launch with `pi --continue` (resume brief) up to `maxAttemptsPerItem`, then mark `needs-human`, record an `escalation` event (delivered by the spec 04 notifier) and comment once.
11. **Budgets and kill switch** `steward/limits.ts`: `maxConcurrentWorkers`, `maxWorkersPerDay`, `itemMinutes` wall clock (interrupt, mark), quiet hours; `durable stop` or the disabled file stops dispatch immediately; running workers finish unless `durable stop --workers`. Acceptance: the (cap+1)th launch is refused; tests + live.
12. **PR attribution** (operator identity, architecture D6): commits authored with the manifest git identity and trailer `Durable-Agent: <id>`; branch `durable/<id>/<item>`; label `durable/agent:<id>`; PR body footer; draft PR. Audit every GitHub write with profile and login. Acceptance: fake-GitHub assertions.
13. **Docs and live pilot.** `docs/workers.md` (templates, extension, dispatcher adapters), `docs/operator.md` (worker lifecycle, viewing workers via `attachInfo`/Orca). Live pilot on one low-risk issue: record the draft PR, audit lines, Orca visibility, machine load, and a `kill -9` of the steward during the worker run. Repeat once with `workers.dispatcher: git-process`.

## Risk controls
- The worker holds the operator's token. Use a fine-grained token limited to the scope's repos, no admin. The guard is a guardrail; branch protection is the real stop. No Workflows write permission.
- Brief and launcher files contain no secrets (env supplies them) and are 0700/0600.
- Only trusted-author items reach the scout.
- Never remove a workspace with uncommitted or unpushed work (adapter contract).
- No `gh pr merge` string in source yet.
- Orca flag drift: the `orca` adapter is the only code that knows the flags; contract tests catch regressions.

## Out of scope
Reviewer, gate, approval, merge, notifications delivery (event recorded only), second machine.

## Done when
CI green including the contract suite; live pilot produced one draft PR through the `orca` adapter and one through `git-process`; replay and cap tests pass; user reviewed PR, audit trail and machine load.
