# Spec 07c — Organizations

Objective: add an optional, cross-machine organization policy boundary that groups durable agents by context. An organization distributes non-secret defaults for pipeline, limits, quiet hours, notifications, repositories, tools and connectors. Profiles remain machine-local credential units: each agent definition names the profile it uses on that machine, and organization policy never stores or selects credentials. An agent without `organization` retains today's behavior through an implicit `default` organization.

Design refs: [organization research](../../research/organizations.md); product review decisions 32-34 and Q29-Q36; architecture D23, D3, D16 and §3; program design §2-3; specs 02, 06b, 07, 07b, 08, 11 and 15.

Depends on: shipped 02-06b and 08, in-flight 06c only for durable-worker coverage, 07 (approval/gate), and 07b (connector enforcement). Slice 11 is required only to distribute an approved bundle to other machines and report fleet state; a single machine and operator-managed file synchronization work without it. It does not change shipped semantics or reorder slices 8-16.

## Checklist

1. **Machine-local files and schema:** load non-secret documents from `organizations/<name>.yaml` beside the existing machine-local agent-definition directory: by default `~/.config/durable/organizations/`, and, when `DURABLE_AGENTS_DIR` overrides the definitions directory, its sibling `organizations/` directory. Do not require a remote, a checkout or Git. Each document has `name`, `memberAgents`, shared settings, default pipeline, limits, quiet hours, notifications, allowed tools, allowed connectors with read/write allow/deny classes, and allowed `scope.repos`. Add optional `organization: <name>` to `AgentDefSchema`; unknown keys, duplicate membership, path-like values and missing named documents fail closed. Acceptance: generated schema/drift and valid/unknown-key/membership fixtures pass.
2. **Apply and approved publication:** `durable org apply <name> --code <nonce>` validates the local candidate, shows the effective diff, and requires an approval-class nonce bound to organization name, parent bundle hash and candidate content hash. On the designated origin machine it records an approved release `{organization, parentHash, contentHash, publisher, approvedAt}` and creates the canonical bundle from the file bytes, content hash and approval record. Bearer tokens, workers and the console cannot apply or publish. Acceptance: nonce replay, wrong-parent/hash, unapproved bundle and audit-redaction tests fail closed.
3. **Distribution and materialization:** the origin's approved, hash-pinned bundle is distributed over slice-11 daemon links by explicit push or member pull. Each receiving daemon verifies the canonical file bytes, content hash, approval record and schema, then materializes an immutable effective configuration for each agent, recording organization name, bundle hash and effective-policy hash. An operator who already synchronizes files with rsync, Syncthing, dotfiles or a shared checkout disables distribution; each daemon instead validates and materializes its local file. Acceptance: origin apply, link push/pull, operator-synchronized files and offline fixtures converge to the same materialization.
4. **Default and migration:** an omitted `organization` resolves to the implicit, in-memory `default` organization, which has no file or sync requirement and permits exactly the existing definition. Do not rewrite existing definitions, machine files or state. Acceptance: fixture snapshots prove pre-organization definition, doctor result, generated environment, dispatch selection and audit semantics are unchanged.
5. **Effective policy and precedence:** compute approved organization defaults then agent definition. Agent definitions may narrow repos, tools, connectors, limits, pipeline, quiet hours and notification delivery. They may not add a repo/tool/connector, change read to write, raise a limit, shorten quiet hours, enable a disabled stage or add notification targets. An attempted loosen is a doctor error, never a silent clamp. An organization update that loosens security-relevant policy is rejected by default and requires a distinct approved apply bound to its exact diff before any member accepts it. Acceptance: precedence and update matrices cover every field.
6. **Local profile resolution and isolation:** materialization never includes a profile, credential alias or credential value. Each agent resolves its own named profile locally after materialization. Environment, source, checkout, dispatch and connector wrappers receive only that profile and the effective organization policy. Acceptance: two machines with different local profile names and contents run the same organization policy; hostile definition, ambient environment and cross-organization access fixtures fail closed for both worker kinds.
7. **Stale, conflict and drift behavior:** a daemon never writes or merges an organization file received from another machine. Invalid local bytes, an unapproved or hash-mismatched bundle, invalid schema or materialized-file drift preserves the last valid materialization and blocks new source, dispatch and connector work when no valid policy exists. An unreachable member is reported `stale`; it may continue under its last valid same-or-stricter policy until `maxStaleAge`, then stops new work while allowing existing fenced work to finish safely. Offline members keep the last verified materialization; doctor reports their version mismatch per machine. Acceptance: disconnect, expiry, divergent files, bad bundle and recovery tests pass.
8. **Doctor, audit, metrics and fleet:** add `durable org list|show|apply|sync <name>` and organization-aware doctor rows for membership, local file/bundle hash, approval, materialization drift and stale age per local agent. Slice-11 fleet groups by organization and reports each reachable member's version state: `current|updating|stale|invalid|unreachable`. Audit, work-item, notification, connector and metric records carry organization id and bundle version. Acceptance: text/JSON/API/SSE/console fixtures identify a version mismatch without exposing policy bodies or credentials.
9. **Approvals and stop controls:** global pause remains global. Per-organization pause/resume fences only member agents. Existing agent-level pause/hold, nonce and passkey bindings remain agent/item/SHA-bound. Organization apply is an approval-class action, distinct from pause or item approval; organization sync cannot release a hold or authorize a merge. Acceptance: pause matrix, restart, nonce/passkey cross-action rejection and global-vs-organization tests pass.
10. **Connector integration:** effective organization connector allow/deny is a mandatory input to spec 07b provider selection and both worker wrappers. A tool must be allowed by agent and approved organization policy; writes require both explicit permissions. Acceptance: allow/deny/read/write/version-mismatch matrices pass, while implicit-default behavior remains unchanged.
11. **Documentation and rollout:** document local file location, `durable org apply`, approval-class publication, bundle transport or operator-managed synchronization, stale behavior, local profile resolution and recovery. Pilot two machines with different profiles and separate repos, including one offline during a tightening update and later convergence. Record answers to Q29-Q36 before live publishing.

## Risk controls

- Plain local files are the organization policy source; no dedicated repository or Git dependency exists.
- The origin distributes only approved, content-hash-pinned bundles; the console/link transports and displays status but does not author policy.
- Operator-managed file synchronization is supported without daemon distribution or slice 11.
- Organization files, approval records, bundles, materializations, caches and audit never contain credentials.
- Every accepted bundle is content-hash pinned and approval-class published.
- Security-relevant policy is tighten-only by default. A loosening update is rejected until separately approved against its exact diff.
- Offline members retain only a last valid bounded policy and stop new work after `maxStaleAge`.
- The implicit default preserves every shipped path without a file or network dependency.

## Out of scope

Organization nesting, multi-user RBAC, organization-owned secrets, a shared database, automatic conflict resolution, changing GitHub identities, and retroactively changing historical audit records.

## Done when

Schema, apply/publication, file/link distribution and materialization, migration/default, precedence, local-profile isolation, stale/drift, doctor, fleet, approval/pause, connector, audit/metrics and two-worker-kind tests pass. A two-machine pilot confirms a tightening update converges, an offline member stops after the stale bound, and no organization path exposes or selects credentials.
