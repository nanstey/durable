# Spec 06c — Durable-conversation worker kind (opt-in, alongside Pi-session)

Objective: add a second worker kind in which the steward asks the dispatcher to create the Orca (or git) workspace/worktree and then runs a **headless pi-durable child conversation** whose cwd and file/shell tools are confined to that worktree. It opens a draft PR through code-owned tools, is visible in the tree and in an Orca `durable attach` viewer terminal, resumes natively after a crash, and is stopped by the kill switch. The Pi-session kind (spec 06) stays the **default**; this kind is opt-in per agent or role.
Design refs: architecture D4 (kinds and capability table), D19 (ownership, tools, kill switch, recovery, skills, storage constraint, human-held rule), D20 (tree and viewer), D9; program design §2 (DW1-DW9, H1-H3, T1-T3, W3), §3.3, §3.4, §5.
New in revision 7 (U6, option 1). Pi-durable references: its README "Abort and Subagents" and examples 22, 23, 24, 26, 28, 29 (github.com/earendil-works/pi). The API is experimental (1.4.0); the slice 1 addendum results must be in `docs/evidence/spike-durable-workers.md` before this spec starts.
Depends on: spec 06 (dispatcher, kind registry, contract suites, hold, viewers), spec 03 (tree API), spec 04 (tree TUI) and the slice 1 addendum.

## Checklist
1. **Kind skeleton** `workers/durableConversation.ts` implementing `WorkerKind` (program design §2): capabilities `{attach: interactive via durable attach, steer: true, transcript: native, interrupt: true, resumeAfterCrash: true, skills: allowlisted-text, extensions: false, anthropicOAuth: modelAuth-option, headless: true, processIsolated: false, tokenInShell: false, viewable: durable-attach}`; selection `workers/select.ts` from `workers.kind` and `workers.durable.roles`. Acceptance: the spec 06 **kind contract suite** passes for this kind with a faux model, including capability reporting and 501 on unsupported operations.
2. **Ownership and anchor** `workers/durable/anchor.ts` (DW1): `run-worker` is a **background** task owned by the item's `WorkItemTask`; the child conversation is created in one transaction with `ownership: { kind: "task", taskId }` and the agent configuration (model, cwd = worktree, fixed tool set, no `subagent`); a rerun reuses it through `scanConversations({ ownerTaskId })`; `details({ conversationId })` lets UIs attach. Acceptance: aborting the steward main conversation or a chat turn leaves the worker running; a restart re-attaches without a second child.
3. **Tool set and confinement** `workers/durable/{tools,confine}.ts` (DW3, DW4): `read`, `edit`, `write` with realpath containment inside the worktree and outside `.git/`; `bash` with cwd = worktree and an environment from `buildAgentEnv(def, "worker")` **without `GH_TOKEN`**; the shared `guard/commands.ts` block-list in `beforeTool` (push, merge, rebase, `reset --hard`, branch switching, `git worktree`, `gh pr merge`, `--admin`, `--force`, `cd`/absolute paths outside the worktree); tool outputs screened for credentials. Acceptance: escape attempts (`..`, absolute paths, symlinks, `cd /`) refused; hostile-env test proves no token in the shell; snapshot of the exposed tool set.
4. **Code-owned git/GitHub tools** (DW5): `commit` (manifest identity, `Durable-Agent` trailer), `push_branch` (only `durable/<id>/<item>`, fixed refspec, remote head checked first), `open_draft_pr` (label, marker, footer; existing PR looked up first), `report`. All are non-replay-safe tools made idempotent by deterministic names. Acceptance: fake-GitHub tests incl. rerun after interruption (no duplicate push/PR).
5. **Kill switch, limits and holds** `workers/durable/limits.ts` (DW2): a `beforeTool` hook checks the kill switch, `human-held` and the item's budgets (`itemMinutes`, `maxTurns`, `maxToolCalls`, token budget from the conversation usage document); the `WorkItemTask` watches the same signals and **explicitly aborts `run-worker`** (crossing the background boundary, writing a terminal outcome); `durable stop --workers` and `pause` use `abort({ background: true })`; daemon `close()` writes no outcome. Acceptance: each of kill switch, hold, budget and wall-clock stops a running worker with a terminal outcome and no resume; `close()` leaves it resumable.
6. **Crash recovery** (DW6): non-replay-safe tools return `interrupted`; steward-authored playbook (`workers/durable/playbook.ts`) tells the model to inspect `git status` and files before repeating; `WorkItemTask` re-attaches after restart. Acceptance: `SIGKILL` mid-`bash`, restart, one worker, one PR; also with `KillMode=control-group` killing tool children.
7. **Skills** `workers/durable/skills.ts` (DW7): **no user skills, extensions, prompts or packages**; `workers.durable.skills` allowlist (default empty) reads `SKILL.md` body text only from the Pi directory's `skills/<name>/`, size-capped, inlined as a prompt section; an entry whose text requires `subagent`, `codemode` or helper scripts is rejected with a clear reason. Document which workflows stay on Pi-session workers (`idea-to-pr`, `build`, `review-code`, `planning`, anything orchestrating subagents or running skill scripts) in `docs/workers.md`. Acceptance: allowlist tests; one real small skill followed by the faux/real model.
8. **Concurrency and storage constraint** (DW8): `maxConcurrent` (default 2; Android 1) enforced in code; the single-owner storage means all durable workers live in the steward process; configurable retention/export/prune of finished worker conversations if the spike showed it is possible. Acceptance: the (cap+1)th start is queued or refused; load test with N children keeps the API and SSE responsive.
9. **Models** (DW9): children use `createModelsFor(profile, providers)`; Anthropic OAuth only when the `modelAuth` option is on; a durable reviewer needs an opposite-family model resolvable before launch or launch is refused. Acceptance: doctor and launch tests.
10. **Tree and viewer:** the worker appears as `worker-durable`/`reviewer-durable` under the steward in `GET /v1/conversations?tree=true`; `durable attach` shows it with follow-up, steer and abort; with `workers.durable.viewer: on-start` the `orca` adapter calls `openViewer` (fallback: command string). Acceptance: tree tests; stub-Orca test for the viewer; live check.
11. **Roles:** reviewer (read-only: `read`, search, a code-owned `pr_diff`) is the first role enabled; code-writing workers are opt-in per agent. Spec 07's reviewer job may use either kind. Acceptance: reviewer flow on the durable kind with a faux model.
12. **Docs and live pilot:** `docs/workers.md` (kinds, capability table, limits, what stays on Pi sessions, confinement is not a sandbox). Live pilot: one low-risk issue with each kind on the same repo; kill the steward mid-run; hold and release; compare results.

## Risk controls
- Pi-session stays the default; no silent fallback between kinds.
- Confinement is cwd + realpath checks + a command denylist, **not a sandbox**; the token is not in the shell; optional container hardening only if the spike justified it.
- Worker progress survives a chat abort or loop tick; the kill switch, hold and limits still stop it with a terminal outcome.
- Experimental pi-durable subagent API: isolated behind `steward/harness.ts` and the kind contract suite; upgrades follow the pin policy.
- Shared process and event loop: `maxConcurrent`, load test, and one steward crash interrupts all in-flight worker tools (documented).
- Two writers in one worktree: the human-held rule applies to this kind too.

## Out of scope
User skills runtime, Pi extensions in durable workers, nested subagents, running durable workers in another process or machine, container/sandbox hardening unless the spike justified a follow-up spec, automatic handoff features.

## Done when
CI green incl. the DW1-DW9 tests and both kind contract suites; live pilot compared both kinds; the user decides which roles use the durable kind (Pi-session remains the default).
