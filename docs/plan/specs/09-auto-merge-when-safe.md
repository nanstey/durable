# Spec 09 — Gate completion, shadow mode and the `RepoPolicySource` seam (no policy mechanism chosen)

Objective: finish the gate's auto path (merge executor, shadow mode) behind a **pluggable `RepoPolicySource` seam** with two built-in sources, `none` (the default; auto-merge off) and a test-only `fixture` source. Fix only the mechanism-independent invariants P1-P6. Do **not** choose or specify how a real repo stores its policy; the user deferred that decision (Q18), and it will be made per repo when the first repo needs auto-merge.
Design refs: architecture D6, D8 (seam, invariants P1-P6, shadow readiness), D9, D15 (`verify-policy` action), §3.6, §5; program design §2 (`policySource`, P1-P6, G5, G8, A1-A5), §3.8, §5 (`gate/*` rows).
Revision 1: throwaway-repo canary removed (C6). Revision 2: renumbered; shadow report also served as `GET /v1/gate/report`. Revision 3: policy moved into the repo with a trust pin (Q9). **Revision 5 (Q18): that fixed design is withdrawn.** There is no policy file name, path, format, trust-pin layout or policy templates in this spec; those are open options.
Depends on: spec 07 (gate, hard-path rule, approval class with the nonce path). The passkey variant of `verify-policy` arrives in spec 12a.

## Checklist

1. **Neutral policy model** `gate/policy.ts`: the `AutoMergePolicy` type the gate consumes (`enabled`, `authors`, `baseBranches`, `pathAllow`, `pathDeny`, `maxChangedLines`, `maxFiles`, `maxRisk`, `requiredChecks`, `methods`, `requireCrossFamilyReview`, `requireHumanApproval`, `coolingOffMinutes`). It is the gate's input contract, **not a storage format**. Acceptance: type tests; a validator that rejects `requireHumanApproval: false` without `enabled: true` and any `pathAllow` entry that matches a hard path.
2. **The seam** `gate/policySource.ts`: `RepoPolicySource { kind, resolve(repo), protectedLocations(repo), describeChange(repo, since) }` and `PolicyResolution { state: verified | unverified | invalid | unavailable | none, policy?, ref, fingerprint }` (architecture §3.6). `scope.repos[].policySource: { kind }` in the definition schema, default `none`; unknown kinds are a doctor error ("source kind not implemented"). Acceptance: schema and doctor tests.
3. **Built-in sources:** `none` (always `state: none`, auto off) and `fixture` (test-only: scripted resolutions for every state, scripted `protectedLocations` and `describeChange`; refused outside tests unless `DURABLE_ALLOW_FIXTURE_SOURCE=1`). Acceptance: both pass the seam contract suite.
4. **Seam contract suite** `tests/contract/policySource.contract.ts` that **every future source must pass**: (P1) a source accepts no path/ref derived from a PR, fork or worktree (lint plus a test that feeds hostile refs); it records the steward-resolved `ref`; (P2) `verified` is returned only after an approval-class action or GitHub-computed evidence (the fixture simulates both and a forging attempt that must fail); (P3) a change to any `protectedLocation` or fingerprint drops `verified` to `unverified`; (P4) every non-`verified` state disables auto-merge and leaves the human-approval path intact; (P5) `effectivePolicy` never loosens; (P6) shadow only. Acceptance: suite green for `none` and `fixture`.
5. **Tighten-only effective policy** `gate/tighten.ts`: `effectivePolicy(resolution, definition)` takes the most restrictive of each field; clamps and records a warning when the definition tries to loosen; `merge.mode: auto-when-safe` without a `verified` policy that says `enabled: true` is ignored with reason `no-verified-repo-policy`. Acceptance: property test (no definition value can raise any limit, widen `pathAllow`, enable auto, or drop `requireHumanApproval`).
6. **Hard paths and protected locations (P3):** PRs touching CODEOWNERS variants (`CODEOWNERS`, `.github/CODEOWNERS`, `docs/CODEOWNERS`), `.github/**` or any `protectedLocation` of the repo's source are `wait-human` (`policy-or-owner-file-change`), never `would-merge`, never auto-merged; the policy state drops to `unverified` until re-verified. Soft-deny paths (lockfiles, secret-like) are allowed only if the verified policy lists them in `pathAllow`. Acceptance: tests against `fixture`.
7. **Shadow mode** `gate/shadow.ts` (P6): with `shadow: true` the gate computes the auto decision for every PR, writes `would-merge | would-not-merge` + reasons + facts snapshot + `{source kind, ref, fingerprint, state}` to the audit log and `steward.gate`, mirrors nothing to GitHub, and the executor follows the human-approval path. **With any non-`verified` state (including `none`) the output is `would-not-merge: <state>` plus a readiness list** of every other gate fact (checks, verdict and family, paths, size, mergeable state, cooling-off) so the operator can see what would otherwise have happened. `durable gate report <id> [--repo] [--since]` and `GET /v1/gate/report` summarize; the console's shadow tab (shell from spec 08) renders it. Acceptance: fixture tests; shadow never calls the merge executor.
8. **Facts for auto** (extends spec 07): author == profile login and in the policy's `authors`; head SHA == reviewed SHA; verdict `approve` from a different family; `mergeStateStatus == CLEAN`; `reviewDecision` not `CHANGES_REQUESTED`; `REVIEW_REQUIRED` => `wait-human` (G8, never bypassed); required checks `SUCCESS`; not draft; policy state `verified` at decision time **and** immediately before the merge call; cooling-off elapsed; base branch allowed; kill switch off; daily cap ok; base branch protected through GitHub-computed state, else only if the verified policy allows it (default no); merge method intersected with the repo's allowed methods from `gh repo view --json squashMergeAllowed,mergeCommitAllowed,rebaseMergeAllowed`.
9. **Merge executor** `gate/merge.ts`: re-read `state`/`mergedAt` first (idempotent); `gh pr merge <n> --<method> --match-head-commit <sha>` (plus `--auto` for merge queues); never `--admin`; interrupted -> re-read before retry; verify `state == MERGED`; audit and a PR comment with the gate report and a revert hint. Reachable only when the definition says `auto-when-safe`, `shadow: false`, the repo's source returns `verified` with `enabled: true`, and the gate says `merge`. With `none` it is unreachable for every real repo.
10. **`verify-policy` approval action:** the CLI nonce path (`durable policy verify <repo>`) with source-supplied display data (`describeChange`), exercised with the `fixture` source; the passkey path is spec 12a. No bearer scope can perform it (A1). `durable policy show <repo>` prints source kind, state, ref, fingerprint and effective policy with clamps. Acceptance: tests; the nonce appears in no log, inbox or GitHub payload.
11. **Lint tests:** only `gate/merge.ts` spawns `gh pr merge`; `--admin`, `--force`, `--no-verify` appear nowhere under `src/` or in the worker-guard allow list; no source module reads from a worktree path or a PR head ref.
12. **Fixture matrix** (`tests/fixtures/github/`, scrubbed recordings: protected and unprotected repos, merge-queue repo, required-review repo, CODEOWNERS repo, plus `fixture`-source scripts for every policy state): each negative case blocks and names its reason: red or pending check, missing or same-family verdict, stale SHA, off-list or denied path, hard path, oversize diff, risk above max, draft, behind base/conflict, kill switch, daily cap, unprotected base, `REVIEW_REQUIRED`, cooling-off, disallowed method, wrong base branch, every non-`verified` policy state.
13. **Post-merge:** release claim, close the item, record outcome, notify `merged`, remove the workspace if clean and merged. Record only; no automatic revert.
14. **Docs:** `docs/operator.md` (modes `never | human-approval | auto-when-safe`, shadow readiness, the seam and its invariants, why `none` is the default, how to read the shadow report, the **open decision** for choosing a source per repo, listing the candidate kinds without recommending one).

## Risk controls

- Default off everywhere: every real repo uses `none`. Real auto-merge cannot be enabled until a source for that repo is chosen, specified and implemented, and passes the contract suite; it additionally needs the definition's `auto-when-safe` with `shadow: false` and GitHub's own rules passing.
- Invariants hold for any future mechanism: nothing is read from a PR head, fork or worker worktree; changes to the policy holder, CODEOWNERS or GitHub rules always need human approval; missing/unverified means off; the definition only tightens; no `--admin` or bypass.
- Missing or unknown facts never merge. One merge per tick. Kill switch, policy state and daily cap are re-checked immediately before the merge call.
- Forgeable GitHub signals are not inputs (G6).
- The `fixture` source cannot be enabled on real repos.

## Out of scope

Any real policy source, file name, path, format or trust-pin layout (open options: in-repo file, GitHub rules/rulesets only, agent-definition-only, out-of-repo store); policy templates; a canary repo; merge queues beyond `--auto`; automatic revert; multi-repo atomic merges.

## Done when

CI green; seam contract suite passes for `none` and `fixture`; fixture matrix passes; shadow mode ran on real PRs with `none` and the operator reviewed the readiness reports; the choice of a real source per repo is recorded as an open decision in the README (not made here).
