# Spec 14 — Android daemon in Termux (additional platform target)

Objective: run a durable agent directly on an Android phone in Termux, working within the phone's limits (no systemd, no Orca, no Tailscale CLI, not always on), without changing the main-line daemon design. The phone can host a daemon and also be the console's browser client.
Design refs: architecture D17 (platform support), D14 (network; peer check optional), D15 (approval classes; nonce unavailable on Android), D4 (`git-process` dispatcher); program design §2 (PL1-PL6), §3.10, §4 (Termux bootstrap), §5 (`platform/*` row).
New in revision 4 (U4). Facts used: Pi runs on Android through Termux (Pi's own Termux doc: install Termux from F-Droid or GitHub, not Google Play; `pkg install nodejs git`; `npm install -g --ignore-scripts @earendil-works/pi-coding-agent`; shared storage needs `termux-setup-storage` and should not hold state). pi-durable's node SQLite storage uses `node:sqlite`; its JSONL storage core is the fallback. Everything else here is a spike check from spec 01's Android checklist, not an assumption.
**Repo: the durable repo only.** Depends on: spec 03 (daemon core, `ServiceManager`), spec 06 (`git-process` adapter, worker kinds) and spec 06c (the durable-conversation kind, the Android default), spec 10 (lease tolerance of a vanishing agent), spec 11 (console connectivity, `peerCheck`), and recommended after spec 12a (the CLI nonce is not available on Android). Requires the slice 1 Android checklist results.

## Checklist
1. **Capability handling** (`platform/*`, already built in specs 02-04): confirm detection on a real device: `os: android` (from `TERMUX_VERSION`/`$PREFIX`), `service: termux-runit`, `tailscaleCli: false`, `dispatchers: [git-process]`, `storage: sqlite|jsonl`, `desktop: termux-notification|none`. Doctor prints detected vs declared and fails on contradictions. Acceptance: tests with stubbed environments plus the live device.
2. **Termux bootstrap** `termux/bootstrap.sh` (idempotent, `ok|copy|update`, safe to run twice, refuses outside Termux): `pkg install` of `nodejs git gh termux-services` (and `termux-api` when requested); Pi via `npm install -g --ignore-scripts @earendil-works/pi-coding-agent@<pin>`; clones this repo at a pinned commit (`--ref`, default the commit the script was fetched at) into `$DURABLE_HOME/vendor/github.com/nanstey/durable`, installs dependencies with the lockfile and `--ignore-scripts` (the daemon's dependencies must be pure JavaScript, PL6), links `~/.local/bin/durable`; takes **no dependency on the skills repo**; records Node, Termux and package versions; prints the manual steps (F-Droid/GitHub Termux build, Termux:Boot, battery-optimization exemption, `termux-wake-lock`). Does not use or extend the skills repo's `install.sh`. **Worker skills (decision, revised in revision 7):** steward, scout, chat **and the default durable-conversation workers need no skills** (the minimal skill-prompt allowlist is empty by default), so the Android bootstrap has no skills-repo dependency in the default configuration; the bootstrap still accepts an optional, separately pinned `--skills-url`/`--skills-ref` that copies the required skill trees into the Pi agent directory, needed only if the operator opts into Pi-session workers on the phone (for example `idea-to-pr`); without them `durable doctor` reports the missing skills and keeps dispatch disabled **only for the Pi-session (kind, role) pairs that need them** (spec 02 item 12), while the skill-free durable workers keep dispatching. Acceptance: a doctor test on a Termux-style config with no skills installed: durable worker and reviewer roles dispatch, an opted-in Pi-session worker role fails closed with the fix message; offline tests with stub `pkg`, `npm`, `sv`, `git` and a temp `$PREFIX`; second run reports all `ok`; a test that no network or skills-repo access happens without `--skills-*`.
3. **`termuxRunit` ServiceManager** `platform/service/termuxRunit.ts` and `termux/{service-run,log-run}.tmpl`: render `$PREFIX/var/service/durable-agent-<id>/{run,log/run}`; `enable`/`disable` via `sv-enable`/`sv-disable`; `start`/`stop`/`status` via `sv`; `logs` from the log dir; the `run` script exports `DURABLE_HOME`, holds `termux-wake-lock` for the service lifetime and `exec`s `durable run <id>` (so `sv down` delivers SIGTERM to the steward itself). **Process cleanup without cgroups:** runit has no `KillMode=control-group` and Termux has no user systemd, so containment is spec 03 item 13b's best-effort Android mode: every subprocess in its own recorded process group with a `DURABLE_INVOCATION` env marker, registered through the gated launch handshake, terminated on SIGTERM shutdown, hold, interrupt and pause, and swept at start before any task resumes. Because a process that drops the marker can escape, a **hold on Android never reaches `held`**: it stays `holding` (fenced). Stopping the steward alone does **not** give the operator exclusive ownership (an unmarked `setsid` descendant survives the steward and the sweep), and `/proc` cannot rule out a future writer (cwd `/`, absolute paths), so before editing the operator must **force-stop Termux or reboot the phone**; `durable hold --verify <item>` is advisory only (spec 06 item 12b). Acceptance adds: `sv down` and `kill -9` of the steward during a `bash` tool that backgrounds a marked child leave no process after restart (stub `sv`; device check); a hold ends in `holding` with the independent-verification message. A Termux:Boot script `~/.termux/boot/durable` starts `termux-services` at boot. Acceptance: the `ServiceManager` contract suite (shared with `systemdUser`) passes with stubs; template snapshot tests; no secrets in service files.
4. **State and secrets placement:** `DURABLE_HOME` and the Pi agent dir live under Termux's private `$HOME`; `doctor` refuses paths under `/storage` or `~/storage`; profile files and `secrets/<profile>.env` keep mode 0600 and a live check confirms Termux honours it. Acceptance: tests and device check.
5. **Android profile and defaults:** a **separate profile** (e.g. `phone`) with its own login and a fine-grained token limited to the small repos this agent touches, shorter expiry (30-day doctor warning), no auto-merge (`merge.mode: auto-when-safe` is a doctor error unless `platform.allowAutoMerge: true`), `maxConcurrentWorkers: 1`, short `itemMinutes`, a repo-size warning (checkout over a configurable limit), optional battery floor through Termux:API (`termux-battery-status`; skipped if absent). Default role (Q21): steward + scout + chat + light workers opening draft PRs on small repos, with the **default worker kind `durable-conversation`** (revision 7: the platform default in the selection precedence, program design §2.1, with platform-default `workers.durable.enabledRoles: [worker, reviewer]` on `os: android`; headless inside the steward, `workers.durable.maxConcurrent: 1`, no sandbox (the guardrails are advisory, R47), no extra process, no TUI, no skills-repo dependency, token not in the shell; `git-process` only provides the git worktree; Pi-session workers are an opt-in; `idea-to-pr` workflows run on desktop machines); the Android `durable attach` viewer is the TUI in Termux or the console in the phone's browser; heavy builds stay on other machines (the scout skips items tagged heavy or over the size limit). Acceptance: doctor rule tests; budget tests.
6. **Network exposure:** implement the option the spike ranked first that works: (1) bind the explicit `network.tailnetAddress` if the Tailscale app's address is bindable from Termux; (2) userspace `tailscaled` inside Termux as a separate tagged node with `tailscale serve --tcp` forwarding to the loopback daemon; (3) loopback only (reachable by a console running on the same phone). Never `0.0.0.0`. `peerCheck: optional`: audit `peer-check: unavailable`; bearer token always required; approval-class actions unaffected (PL4). Acceptance: bind tests with stubbed interface enumeration (including the case where `os.networkInterfaces()` throws); doctor messages; live reachability from another tailnet node.
7. **`desktop` backend** `platform/notifier/termuxNotification.ts` (`nonceSafe: false`): uses `termux-notification` when Termux:API is present, else `none`. The CLI approval nonce is never sent to it (PL3); approvals for this daemon need an enrolled passkey (spec 12a) or a GitHub merge, and the console says so. Acceptance: tests that the nonce never reaches this backend; notification test on the device.
8. **Offline-tolerant behaviour:** after a kill/restart or long sleep the daemon re-derives claims, workers and queue state from GitHub and the dispatcher before acting (existing S1) and starts conservative (budget windows keep counting); `agent-down` cannot be self-reported, so the console's `offline` state and lease expiry are the signals (documented). Acceptance: restart tests; a device check where the phone sleeps overnight and another machine takes over a claim after the lease expires.
9. **Console integration (spec 11):** the device appears with platform capability badges (`android`, `git-process`, `peer check unavailable`), shows `offline` when unreachable, and `unauthorized`/`mismatch` as usual; running the console in Termux on the same phone and opening it in the phone's browser over loopback is documented and checked.
10. **Docs:** `docs/operator.md` "Android" section: install steps, what the phone agent does and does not do, battery and Doze guidance, phantom-process note (to be confirmed on the user's Android version), token/profile separation, device lock and encryption assumption, remote wipe and `durable token revoke`, proot-distro not used (Q22).
11. **Live validation on a device:** run through the slice 1 Android checklist results; kill and restart recovery; overnight run with Doze (record tick gaps); a draft PR from a light durable-conversation worker on a small repo (and, optionally, one from a Pi-session worker); console online/offline transitions; claim-expiry takeover by another machine; battery and thermal notes; audit shows the phone profile's identity on every write.

## Risk controls
- A phone is easier to lose or steal: separate profile and token scoped to few repos, 30-day expiry, no auto-merge, human merge by default; assume device lock and Android file-based encryption (not verifiable by `doctor`); revoke tokens and keys on loss.
- No `0.0.0.0` binding; peer check unavailable is made visible, not silently passed; ACLs at the tailnet level still apply.
- No nonce-safe channel on Android: approvals use passkey or GitHub merge.
- Android may kill the process at any time: all effects are intent-first and re-derived (S1); leases cover vanishing.
- Termux package drift (`pkg upgrade` changing Node) is contained by recorded versions and the bootstrap's `ok|update` reporting; the daemon uses only pure-JS dependencies installed with `--ignore-scripts`.

## Out of scope
Orca on Android; proot-distro; heavy builds or long test suites on the phone; auto-merge on Android; iOS; running the console server as a required component on the phone; using shared storage for state.

## Done when
CI green (offline tests); live device validation recorded; the user has lived with the phone agent for several days and decided whether phone workers stay enabled.
