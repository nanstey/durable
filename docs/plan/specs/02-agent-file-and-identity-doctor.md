# Spec 02 — Durable repo scaffold, profiles, definitions, machine file and identity `doctor`

Objective: one credential unit (the profile) referenced by name from agent definitions, a machine-local file for assignment/paths/channels, and `durable doctor` proving which identity an agent would use. No daemon yet.
Design refs: architecture D2, D3, D6, §3.1-3.2; program design §1 (layout), §2 (P1, I1-I3), §4; architecture D18.
Revision 1: replaces "per-agent file declares identity" (C1, C3); GitHub identity is the operator's (C2).
Revision 2: machine file gains `name`, port assignment (`agents: [id | {id, port}]`, `daemon.portBase`) and channel kinds limited to `console|desktop|command|github` (no ntfy); `network` and `approval` blocks parse but doctor reports them as `not-yet-supported` until slices 11/12.
Revision 5: definition schema carries `policySource` (seam only, Q18) and a minimal `chat:` block (no default rate limits, Q20). Revision 4: machine file gains `platform` (`os`, `service`, `tailscaleCli`, `allowAutoMerge`), `network.peerCheck` and `network.tailnetAddress`; `platform/{detect,capabilities}.ts` detect capabilities (Termux vs Linux, `systemctl --user`, `tailscale` on PATH, `node:sqlite`, Orca reachability) and doctor reports detected vs declared, failing on contradictions; Android rules PL3-PL5 (no auto-merge ceiling, no `DURABLE_HOME` under `/storage`, nonce-safe channel checks) are implemented as doctor checks even though no Android daemon exists yet. Revision 3: definition schema gains the `merge` **ceiling** (`mode`, `shadow`, `tighten.*` that can only restrict; the policy itself comes from the repo's `RepoPolicySource`, spec 09), a per-repo `policySource: { kind }` (default `none`; unknown kinds rejected until implemented), a `chat:` block (`startableKinds` (console-wide), `maxMessageBytes` sanity ceiling default 1 MiB, optional opt-in `rateLimit`; no default rate limits, Q20), and `workers.dispatcher`; Linux/systemd only (no launchd). Doctor warns if `tighten` tries to loosen the resolved policy.
Revision 6 (U5): all paths are repo-root paths of the **durable repo** (`nanstey/durable`); this spec no longer touches the skills repo (the installer step, thin skill, catalog row and Pi-README row moved to spec 02b); it adds the repo scaffold, CI, the public-repo **hygiene scan** and a required-skills doctor check.
Depends on: spec 01 (version pins, symlink result, Anthropic option for the `modelAuth` seam).

## Checklist
1. **Scaffold the repo** (durable repo, root): `package.json` (`@nanstey/durable`, `"type": "module"`, `engines.node >=22.19`, `files` excluding `spike/`, `docs/plan/` optional), `pnpm-lock.yaml`, `tsconfig.json` (`erasableSyntaxOnly`), `bin/durable`, `AGENTS.md` (public repo rules, commit conventions), existing `LICENSE` kept. **Exact** pins from the spike (pi-durable 1.4.0 and the matching pi-ai and pi-coding-agent, `typebox`, `yaml`; dev: `typescript`, `@types/node`). Branch flow respects the protected `main` (PRs, squash-only). Acceptance: `pnpm install --frozen-lockfile` in a fresh clone; `tsc --noEmit` passes.
2. **Schemas + loader** `src/config/{schema,agent,machine,manifest,load,paths}.ts`: agent definition, machine file, profile manifest (architecture §3.1, §3.2, D3). Reject unknown keys; `peers` must be `[]`; `network.bind` = `loopback`; `merge.mode` default `human-approval`; **definition validator rejects absolute or `~` path fields and hostnames**; `profile` must match `^[A-Za-z0-9._-]+$`. Paths: `DURABLE_HOME`, `DURABLE_AGENTS_DIR` (default `~/.config/durable/agents`), machine file `~/.config/durable/machine.yaml`. Acceptance: table tests (valid, unknown key, path-like field, bad profile name, agent not in machine `agents`, definition missing).
3. **Generated JSON Schemas** under `schema/` + a drift test.
4. **Profile resolution** `identity/profiles.ts`: mirror `@nanstey/pi-auth-profiles` (`default` -> `$PI_AGENT_DIR/auth.json`, `<name>` -> `auth-profiles/<name>.json`), `secrets/<name>.env`, `profile-meta/<name>.json`. No fallback (P1). List providers via `AuthStorage.list()` without resolving secrets. Read-only. Acceptance: tests with temp agent dir.
5. **Manifest CLI** `cli/profile.ts`: `durable profile init <name>` (writes manifest skeleton, 0644, refuses overwrite), `bind-github <name>` (runs `gh api user --jq .login` with that profile's `GH_TOKEN` and writes the login; prints it for confirmation), `show`, `list`, `check`. Acceptance: tests with stub `gh`; no secret ever printed.
6. **Env builder** `identity/env.ts`: allowlist env + `GH_TOKEN`/`GITHUB_TOKEN` from `secrets/<profile>.env` + `GH_CONFIG_DIR`, `GIT_CONFIG_GLOBAL` (generated from the manifest: user.name/email, `credential.helper`, HTTPS rewrite, `Durable-Agent` trailer config), `GIT_CONFIG_SYSTEM=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `PI_CODING_AGENT_DIR`; scrub ambient provider keys and `SSH_AUTH_SOCK`. Acceptance: snapshot test with a hostile parent env.
7. **Derived Pi dir** `identity/pidir.ts`: generated `settings.json`, `auth-profiles.json` pinning `defaultProfile`, symlinks (`auth-profiles/`, `secrets/`, `profile-meta/`, `extensions/`, `skills/`, `agents/`, `prompts/`, `npm/`, `vendor/`); **no `auth.json` unless the profile is `default`** (then a symlink). Acceptance: layout test plus a real `AuthStorage.modify` through the symlink (lock + rename safe, symlink intact). If the spike or this test fails, use the spike's recorded alternative; copying the profile file is NOT acceptable (refresh rotation).
8. **Token checks** `identity/{github,token}.ts`: `gh api user` login vs manifest login; token type from prefix (`github_pat_` ok; `ghp_` and `gho_` warn); `x-oauth-scopes` containing `admin:*`/`repo` broad scopes warn; list of repos reachable beyond the definition's scope when detectable (warn). Acceptance: stub `gh` tests.
9. **Model-auth seam** `identity/modelAuth.ts`: `createModelsFor(profile, providers)` with the `plain` implementation (file-backed `AuthStorage`); the `anthropicShaped` variant is stubbed to throw `not-configured` until the spike choice is built (separate follow-up if option 1 or 2 wins; add a spec 02a at the slice 1 checkpoint). Acceptance: test with an API-key profile.
10. **Doctor** `identity/doctor.ts` + `cli/doctor.ts`: checks = definition valid, agent assigned in `machine.yaml`, profile exists on this machine (**fails closed with exact fix steps**: Pi `/login` for named providers, `pi-secret -p <name> set GH_TOKEN`, `durable profile init <name>`), manifest present, token login equals manifest login, git identity, providers for steward/worker/reviewer models present, reviewer family differs from worker family, `gh` and Node present, `workers.dispatcher` resolvable (adapter exists; Orca reachability is checked in slice 6), channels referenced by the definition exist in `machine.yaml` and are of an allowed kind; a `github` channel's `targetLogin` differs from the profile's manifest login (else warn: silent); port assignments have no collisions. Output a table; exit 1 on any failure; `--json`. Acceptance: one test per failing check.
11. **CLI skeleton** `bin/durable.ts` with `doctor`, `profile`, `help`; `--dry-run`.
12. **Required-skills check** `identity/skills.ts` + doctor row: verify the configured required skills exist under the Pi agent directory's `skills/` (default list `idea-to-pr`, `pr`, `build`, `review-code`; override in the machine file); a missing skill yields a fix message ("install the skills repo integration or copy the skill trees") and **disables worker dispatch** for that machine while steward, scout and chat still work. The list and ownership are documented in `docs/skills-contract.md`. Acceptance: tests with a temp Pi agent dir.
13. **Docs.** `README.md`, `docs/install.md` (standalone install: clone, `pnpm install --frozen-lockfile --prod --ignore-scripts`, link `bin/durable`), `docs/operator.md` (profiles, `pi-secret -p`, manifest, definitions vs machine file, `doctor`), `docs/skills-contract.md`, `docs/architecture.md` (pointing at `docs/plan/`), `examples/` (`agent`, `machine`, `profile-meta`; placeholders only), a one-line "inspired by `disler/durable-pi`" reference (no code from it). Move the plan here: `docs/plan/` (this plan folder, links relative).
14. **CI and public-repo hygiene.** `.github/workflows/ci.yml`: install with the frozen lockfile, `tsc --noEmit`, `node --test test/unit`, and `scripts/hygiene-scan.sh` over the **whole repo including `docs/plan/` and `docs/evidence/`**. The scan fails on: home or user paths (`/home/<name>`, `/Users/<name>`), real-looking emails (allowlist `*@example.invalid`, `*@example.com`), token prefixes with token-shaped bodies (`ghp_`, `gho_`, `github_pat_`, `sk-`, `sk-ant-`, `AKIA`), private-key headers, tailnet names (`*.ts.net`) and Tailscale CGNAT-range addresses, `.env`-like files, and non-placeholder host names in `machine`/`console` examples; placeholders (`<console-host>`, `<operator-login>`, `acme/api`) pass; exceptions live in `scripts/hygiene-allow.txt` with a reason per entry. Acceptance: `test/hygiene.test.ts` with positive fixtures that must fail and placeholder fixtures that must pass; the scan is green on the plan folder. Whether the repo's CI is also required on `main` is a settings change the owner makes when slice 2 merges.
15. **Manual verification** (record in the plan README `## Slices`): `durable profile bind-github` and `durable doctor` on two real profiles; swap `GH_TOKEN` to see the mismatch; run an agent assigned to a machine without the profile and read the fix text.

## Risk controls
- Doctor and profile commands never print tokens or credential file contents.
- Tests never write to the real `auth.json`/profile files.
- Public repo: no absolute or personal paths, hostnames, tailnet names, emails or secrets in committed files; examples use placeholders and `~`-relative paths only, and definitions use repo slugs; enforced by item 14.
- Keep `identity/` free of pi-durable imports (pi-ai and pi-coding-agent only).
- Fine-grained token guidance is advisory in `doctor`; it never blocks on a warning.

## Out of scope
Steward process, systemd units, GitHub polling, dispatcher, notifications, and everything in the skills repo (spec 02b).

## Done when
Items 1-14 pass in the durable repo's CI (including the hygiene scan over the plan folder), item 15 recorded.
