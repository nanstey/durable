# Spec 03 — Steward process and remote-ready daemon API v1

Objective: one durable process per agent under systemd --user that ticks, survives `kill -9`, writes an audit log and an inbox, and serves a **versioned, scoped, remote-ready API** that the CLI, the TUI and the console will all use. Read-only toward GitHub. Loopback only in this slice.
Design refs: architecture §1, D1, D3, D9, D10, D14 (API and tokens), D15 (credential classes), §3.3-3.4, §5; program design §2 (D1-D4, A1), §3.1, §3.2 (tick only), S1-S4.
Revision 7 (review): the unit sets `KillMode=control-group` explicitly with a no-orphan test; every subprocess runs in an item/attempt containment unit (a transient systemd user scope in a per-attempt slice on Linux; process group + env marker on Android) registered through a gated launch handshake, and stale units are killed at start before any task resumes (round 2); emptiness is the recursive cgroup v2 `populated 0` of the slice, the gate execs only on an exact release token, a `releasing` state precedes the release, every spawned state is treated as live, and records survive failed cleanup (round 3); hold fences are recovered before unfinished tasks resume; `stop`, `pause`, `abort` and the other lifecycle operations follow the single table in program design §2.2.
Revision 5: chat has no default rate limits (audit, screening, fixed tools, budgets and the kill switch remain; 1 MiB sanity ceiling; opt-in rate limit). Revision 4: service management is behind the `ServiceManager` interface (`platform/service`, with the `systemdUser` implementation here; `termuxRunit` arrives in spec 14) and storage is chosen by capability (`sqlite` via pi-durable's node SQLite storage, `jsonl` fallback); the daemon core imports nothing systemd-specific (PL1). Revision 1: profile-based startup (C1), `modelAuth` seam, `OnFailure` unit stub. Revision 3: scope `steer` renamed **`chat`** (messages, abort turn, start/resume conversations, worker steer where supported); chat guardrails (rate limit, size cap, credential screening, audit) land here because every client shares them. Revision 2: API shaped for remote clients (U2): scoped hashed tokens, SSE `hello -> snapshot -> deltas`, device identity, inbox; attach/TUI moved to spec 04.

    13b. **Process containment and launch handshake** `steward/procs.ts` (S5): every subprocess the steward spawns (code-run `gh`/`git` now; a test-only slow tool in the tests; Pi-session worker processes in spec 06; durable-worker `bash` and code-owned git in spec 06c) runs inside a **containment unit** and is registered before it can run any work.

- **Containment.** **Linux:** each invocation runs in its own transient systemd user scope inside a per-attempt slice: `systemd-run --user --scope --collect --slice durable-<agent>-<item>-<attempt>.slice --unit durable-<agent>-<item>-<attempt>-<n> -- <gate> <argv>` (steward-internal calls without an item use `durable-<agent>-steward.slice`). The cgroup holds every descendant, including ones that leave their process group (`setsid`, double fork) or whose group leader exited. `containAttempt.kill()` = `systemctl --user kill --signal=TERM` on the slice, 5 s grace, then `KILL`, then wait until the slice is **recursively empty**: read `cgroup.events` of the slice's cgroup directory (path from `systemctl --user show -p ControlGroup`, under the cgroup v2 mount) and require `populated 0` (the kernel defines `populated` over the whole subtree, so child scope cgroups count; the slice's own `cgroup.procs` is always empty because processes live in the child scopes and is never used). Requires the cgroup v2 unified hierarchy (doctor check); on cgroup v1 the machine is treated like Android for containment. If the scope cannot be created, the invocation **fails closed** (it never runs outside containment). **Android/Termux (no user systemd, no cgroups):** best-effort containment only: own process group, plus an env marker `DURABLE_INVOCATION=<id>`; kill = signal the recorded groups, then every process of the user whose `/proc/<pid>/environ` carries a marker of that attempt. A process that drops the marker escapes; such an item therefore can never be confirmed empty (see hold, spec 06 item 12b).
- **Launch handshake** (no gap between spawn and registration): (1) commit `{invocationId, attemptId, item?, unit/slice name, state: intent}` to `steward.procs`; (2) spawn the containment unit running the **gate** `bin/durable-gate` (a small Node program, no shell) with the expected token's SHA-256 in its argv and a pipe on fd 3; it blocks reading **one line** from fd 3 and `exec`s the target **only if** the line's SHA-256 equals the expected hash (a per-invocation random release token, compared in constant time); on EOF, a read or descriptor error, invalid or oversized input, a mismatch or a 60 s timeout it **exits non-zero (97) without exec**; (3) read and commit the actual identity `{pid, start time, pgid, cgroup path or marker}` (`state: registered`); (4) commit `state: releasing` **before** writing the token; (5) write the token to fd 3 and close it, then commit `state: running`; (6) on exit, delete the record only after the unit is confirmed empty (Linux: slice `populated 0`). **Recovery at start, before any task of the affected item resumes:** every state from `intent` onward is treated as **potentially live** (a crash can fall on either side of any commit or external action): find the unit and slice by their deterministic names (`systemctl --user show`; Android: recorded group + marker scan), kill them, and wait for confirmed emptiness (Linux: slice `populated 0`, also for `intent`, where a unit may or may not exist; Android: recorded groups and marker-matched processes gone, pid start times checked so a reused pid is never killed); a slice whose leader exited but whose members remain is covered by the recursive cgroup check on Linux and by the marker scan on Android. A record is deleted **only after** confirmed cleanup; if cleanup fails or times out the record is **kept**, the item gets a `recovery` fence (enforced like a hold fence, H4) so none of its tasks can act, the failure is audited and an `escalation` is sent; the next start retries. Every kill is audited.
- Uses: `terminate(item|attempt|task)` for hold, interrupt-hard, pause, `stop --workers` and SIGTERM shutdown; the start-up sweep above. This is defence in depth beside the service unit's `KillMode=control-group`, and the only cleanup on Android.
- Acceptance: **gate tests**: the target never runs on EOF (writer closed without a token), a read error (fd 3 closed or invalid), empty, oversized or wrong token, or timeout, and the gate exits 97 in each case; it runs only with the exact token; **crash-before-registration**: SIGKILL the steward after spawn and before the `registered` commit, restart: the target's marker file was never written, the unit is killed and the slice reaches `populated 0`; **both sides of every boundary** (a fault-injection hook kills the steward immediately before and immediately after each commit (`intent`, `registered`, `releasing`, `running`, record delete) and each external action (spawn, token write, kill)), then restart: no target ran where the token was never written, every unit is killed and confirmed empty before the item's tasks resume, and no record is lost; **cleanup failure**: a stubbed kill that leaves the slice populated keeps the record, fences the item with `recovery` and escalates; **recursive emptiness**: a fixture cgroup tree whose slice `cgroup.procs` is empty while a child scope is populated (`cgroup.events` `populated 1`) is **not** treated as empty; a tool that backgrounds a `sleep` child, a `nohup` grandchild and a **`setsid` delayed writer** (`setsid sh -c 'sleep 10; echo x >> f' &`): on Linux `terminate` leaves the slice at `populated 0` and `f` unchanged after 15 s; scope creation failure (stub `systemd-run` exits 1) -> invocation refused; on a stubbed Android platform the marker scan kills marked descendants and an unmarked `setsid` child is reported as unconfirmed; a reused-pid fixture is not killed.

- Loopback bind enforced in code.
- No GitHub writes in this slice.
- The API is the surface for every later client; changes after this slice are additive inside `/v1`.
