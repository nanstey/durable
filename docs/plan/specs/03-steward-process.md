# Spec 03 — Steward process and remote-ready daemon API v1

Objective: one durable process per agent under systemd --user that ticks, survives `kill -9`, writes an audit log and an inbox, and serves a **versioned, scoped, remote-ready API** that the CLI, the TUI and the console will all use. Read-only toward GitHub. Loopback only in this slice.
Design refs: architecture §1, D1, D3, D9, D10, D14 (API and tokens), D15 (credential classes), §3.3-3.4, §5; program design §2 (D1-D4, A1), §3.1, §3.2 (tick only), S1-S4.
Revision 7 (review): the unit sets `KillMode=control-group` explicitly with a no-orphan test; every tool subprocess runs in its own recorded process group and stale groups are terminated at start before any task resumes (the cleanup that also serves Android, which has no cgroups); hold fences are recovered before unfinished tasks resume; `stop`, `pause`, `abort` and the other lifecycle operations follow the single table in program design §2.2.
Revision 5: chat has no default rate limits (audit, screening, fixed tools, budgets and the kill switch remain; 1 MiB sanity ceiling; opt-in rate limit). Revision 4: service management is behind the `ServiceManager` interface (`platform/service`, with the `systemdUser` implementation here; `termuxRunit` arrives in spec 14) and storage is chosen by capability (`sqlite` via pi-durable's node SQLite storage, `jsonl` fallback); the daemon core imports nothing systemd-specific (PL1). Revision 1: profile-based startup (C1), `modelAuth` seam, `OnFailure` unit stub. Revision 3: scope `steer` renamed **`chat`** (messages, abort turn, start/resume conversations, worker steer where supported); chat guardrails (rate limit, size cap, credential screening, audit) land here because every client shares them. Revision 2: API shaped for remote clients (U2): scoped hashed tokens, SSE `hello -> snapshot -> deltas`, device identity, inbox; attach/TUI moved to spec 04.
Depends on: spec 02, and the **slice 1 addendum** (spec 01 "Addendum done when"): its tree-enumeration (item 9), cancellation (item 2) and process-group (item 10) results must be recorded as go before items 6a and 13b start.

## Checklist
1. **pi-durable adapter** `steward/harness.ts` (the only pi-durable importer): SQLite at `$DURABLE_HOME/agents/<id>/state.sqlite`, registry, `models = identity/modelAuth.createModelsFor(profile, providersOf(def))`, ensure the main conversation and the `steward-loop` repeat task exist. Acceptance: contract test opens, commits an entry, closes, reopens.
2. **Process entry** `steward/main.ts`: load machine file (agent assigned here), definition and manifest, `doctor.lite()` (fail closed + audit with fix text), lock file, open harness, start API, SIGTERM graceful `close()`. Acceptance: second instance exits non-zero.
3. **Loop skeleton** `steward/loop.ts`: tick = kill-switch check, budget rollover, heartbeat document, audit `tick`, `{again:{nextAt}}`. Acceptance: faux-model test ticks twice with a fake clock.
4. **Kill switch & limits** `steward/{killswitch,limits}.ts`: per-agent `disabled` file, global `$DURABLE_HOME/disabled`, `DURABLE_DISABLED=1`, quiet hours parser; budget document. A `pause` (token scope) writes the disabled state with the effects listed for `pause` in the lifecycle table (program design §2.2); **resume** is not a token operation (reserved for approval credentials, spec 07/12; until then resume = `durable resume` on a TTY on the machine). Acceptance: unit tests; paused agent audits `paused` and acts no more.
5. **Chat guardrails** `api/chat.ts` on `POST .../messages` (D16, CH1-CH4): plain-text body only (no role/attachment/HTML/tool-call field), a **sanity ceiling of 1 MiB** (default, `chat.maxMessageBytes`) that exists only to protect the daemon process from a runaway client or loop; **credential screening** (GitHub token prefixes `ghp_`/`gho_`/`github_pat_`, `sk-`/`sk-ant-` keys, private-key headers, common cloud key patterns, long high-entropy strings) => `400 invalid` code `credential-like-content`; **no default rate limits (Q20)**: runaway cost stays bounded by the existing per-agent budgets and the kill switch; rate limiting is **opt-in** per agent (`chat.rateLimit`, default off) and then returns `429` with `Retry-After`, with counters in `steward.chat`; **audit** `{actor: human, via, client, conversationId, bytes, sha256}` (no content). Acceptance: positive/negative screening cases (from the spike's sample), audit record test, 1 MiB ceiling test, a test that no rate limiting happens by default, and window tests with a fake clock only for the opt-in setting.
5b. **Audit** `steward/audit.ts`: append-only JSONL, `fsync` per line, redaction helper, schema per architecture §3.4. Acceptance: concurrent-append and redaction tests.
6a. **Conversation tree** `tree/{nodes,build,frames}.ts`, routes `GET /v1/conversations?tree=true`, `GET /v1/conversations/<id>`, `GET /v1/conversations/<id>/{transcript,events}`, `POST /v1/conversations/<id>/{messages,abort}` for every node kind (`abort` = abort the node's current turn only, lifecycle table row 1; it never ends a worker attempt), and `tree` SSE frames in the steward scope (architecture D20). Node shape `{id, parentId, kind, status, item?, ownerTaskId?, source, workspace?, startedAt, capabilities}` with `kind` in `steward|chat|scout|worker-durable|reviewer-durable|worker-pi|reviewer-pi|subagent`; built from the durable ownership index and `taskGraph` (spike addendum item 9); dispatcher-sourced nodes (Pi sessions) are added by spec 06. Chat/scout/steward nodes exist here; the `capabilities` object drives which controls clients show (T2). Acceptance: tree builder tests with a fixture steward (nested children); `tree` frame delta test; scope matrix covers the new routes; node ids opaque.
6. **API v1 contract** `api/{types,routes,sse,auth,tokens}.ts` per architecture §3.3: `GET /healthz`; `GET /v1/device` (`apiVersion`, `durableVersion`, `uid` generated once and persisted, `machine` name, `agent`, profile **name** only, scope summary, `capabilities`, `startedAt`); `GET /v1/sessions`, `.../transcript?format=json|markdown`, `.../events` (SSE), `.../tasks`; `POST .../messages` (required `requestId`, `whenBusy`), `POST .../abort`; `GET /v1/audit?since=`; `GET /v1/inbox`, `POST /v1/inbox/<id>/ack`; `GET /v1/budget`; `POST /v1/pause`. Error shape `{error:{code,message}}` with `unauthorized`, `forbidden`, `not_found`, `invalid`, `busy`, `conflict`, `rate_limited`, `not_supported`, `unavailable`, `internal`. Types exported for clients. Acceptance: contract tests against the typed client in spec 04's faux daemon (stub until then).
7. **SSE** `api/sse.ts`: each connection sends `hello {apiVersion, scope, serverTime}`, a snapshot, then deltas; `: ping` every 15 s; reconnect = new snapshot (no replay); viewers more than 2 MB behind are disconnected; closing never stops work. Acceptance: ordering test; reconnect snapshot test; slow-viewer test with a fake clock.
8. **Scoped tokens** `api/{auth,tokens}.ts`: `durable token create --client <name> --scopes read,chat,pause [--expires 90d]` prints the token once; storage `agents/<id>/tokens.json` (0600) holds only SHA-256 hashes, client name, scopes, created/last-used/expiry; `list`, `revoke`; the local CLI uses its own token file (0600) with the same rules. Scope table: `read` = all GET; `chat` = `POST .../messages`, `POST .../abort`, conversation start/resume (spec 04), worker steer (spec 06); `pause` = `POST /v1/pause`, worker interrupt (spec 06), item hold `POST /v1/items/<item>/hold` (spec 06). Item release is approval-class (spec 06 item 12b), never a scope. **No scope covers approve, agent resume, enroll or policy verification (A1).** Constant-time compare. Acceptance: scope matrix test (every route x every scope), hash-only storage test, expiry/revocation tests, no endpoint returns a token.
9. **Listeners** `api/net.ts`: loopback only in this slice; any other `network.bind` is rejected with a clear doctor message ("available from slice 11"). Acceptance: bind test; config with `tailnet` refused.
10. **Inbox** `steward/inbox.ts`: `steward.inbox` document (events with id, type, agent, target URL/ref, created, acked); written by the notifier (spec 04) and the steward (identity failure, budget stop, paused). Never stores secrets, bodies or nonces. Acceptance: persistence across restart; ack test; grep test for secret-like strings in fixtures.
11. **Main conversation (narrow)**: system-prompt section, tools `list_queue` (empty for now), `status`, `pause`; no bash, no GitHub write. Acceptance: tool list test.
12. **CLI commands** (minimal): `durable status`, `enable`/`disable` (refuses an agent not listed in `machine.yaml`; `systemctl --user enable --now durable-agent@<id>`), `stop` (service shutdown = `close()`, lifecycle row 7: no outcomes written, unfinished work resumes on the next start), `pause`, `resume` (TTY), `logs`, `token`. Acceptance: `--dry-run` prints the command; stubbed `systemctl` tests.
12b. **ServiceManager interface** `platform/service/{types,systemdUser}.ts` per program design (install, enable, disable, start, stop, status, logs, failure hook) and the CLI (`enable`, `disable`, `stop`, `logs`) calling it instead of `systemctl` directly; storage capability selection in `steward/harness.ts`. Acceptance: `ServiceManager` contract suite run against `systemdUser` with a stub `systemctl`; a lint test that nothing outside `platform/` mentions `systemctl` or `notify-send`.
13. **Units** `units/durable-agent@.service` (`ExecStart=%h/.local/bin/durable run %i`, resolving the CLI symlink whichever way durable was installed, `Restart=on-failure`, **`KillMode=control-group` set explicitly** (never `process` or `mixed`; the spike saw a `kill -9`'d process's `bash`/`sleep` children survive), `TimeoutStopSec=30`, `NoNewPrivileges`, no secrets, `Environment=DURABLE_HOME` only if non-default) and `durable-agent-failure@.service` (`OnFailure=` target; placeholder command here, wired to `durable notify --event agent-down` in spec 04). `durable enable <id>` (through the `ServiceManager`) renders and installs the unit into `~/.config/systemd/user/` and enables it; no installer renders units and the skills repo never touches them. Document `loginctl enable-linger`. Acceptance: `systemdUser` contract tests with a stub `systemctl` (render, enable, status, failure hook); a render test asserting `KillMode=control-group` is present.
13b. **Tool process groups** `steward/procs.ts`: every subprocess the steward spawns (code-run `gh`/`git` now; a test-only slow tool in the tests; durable-worker `bash` and code-owned git in spec 06c) is spawned detached in its **own process group**; before spawn the steward commits `{pgid, pid start time, owner task, item?}` to `steward.procs`, and removes it when the group is gone. Uses: (a) `terminateGroup(item|task)` (TERM, 5 s grace, KILL; used by hold, interrupt-hard, pause and SIGTERM shutdown); (b) **start-up cleanup**: before `harness.open()` resumes any task, every recorded group still alive (pid start time matches, so a reused pid is never killed) is terminated and audited. This is the Android/runit equivalent of `KillMode=control-group` and defence in depth on Linux. Known limit (documented): a descendant that leaves its group (`setsid`, double fork) escapes (a); the cgroup kill covers it on Linux; on Android it is reported by the advisory scan (processes whose cwd is inside an item worktree and that durable did not record). Acceptance: tests with a tool that backgrounds a `sleep` child and a `nohup` grandchild: `terminateGroup` leaves none; SIGKILL the steward, restart, the recorded groups are killed before any task resumes; a reused-pid fixture is not killed.
14. **Recovery test** `tests/contract/recovery.test.ts`: faux model; start; `SIGKILL` during a tick; restart; one loop task, intact heartbeat doc, intact tokens and inbox. **No-orphan test:** `SIGKILL` the steward while the test-only tool runs `sleep 300 & sleep 300`; after restart no process from the old run remains (13b; and, in the live drill under systemd, `systemctl --user show -p ControlGroup` lists no stale pids).
15. **Live drill** (record): enable on a real machine; `curl` with a `read` token (device, SSE, transcript, inbox); a message post with a `read` token gets 403; `kill -9` during a slow `bash` tool -> restart, and confirm with `ps` that the tool's children are gone (`KillMode=control-group`); `pause`; verify no tick; `durable resume` on the TTY.
16. **Docs**: `docs/daemon.md` (daemon, units, CLI), a section in `docs/operator.md` on API v1 and tokens, `docs/api.md` for the v1 contract.

## Risk controls
- Token files and `tokens.json` mode 600; hashed storage; unit file free of secrets; logs redacted.
- Loopback bind enforced in code.
- No GitHub writes in this slice.
- The API is the surface for every later client; changes after this slice are additive inside `/v1`.

## Out of scope
Attach TUI (spec 04), sources, claims, workers, gate, tailnet bind (spec 11), approvals (specs 07, 12), console.

## Done when
CI green; recovery test passes; live drill recorded; user has inspected the API with `curl` and judged it fit for remote clients.
